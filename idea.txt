================================================================================
ARCHITECTURAL BLUEPRINT: THE 'OMNISHOCK' VIRTUAL 3D ENGINE (dot.py)
================================================================================
VISION:
An autonomous, high-performance 1st-person 3D raycasting engine and stateful 
immersive sim constructed entirely from scratch using the Python Standard Library. 
The system fuses the core rendering restrictions of WOLFENSTEIN 3D and DOOM (1993) 
with the dense, terminal-driven, environmental storytelling of SYSTEM SHOCK 
and the branching, multi-solution choice matrices of DEUS EX. The entire simulation 
must manifest through an ASCII grid frame buffer with deep computational efficiency.

The codebase must implement five tightly synchronized core engine modules.

--------------------------------------------------------------------------------
1. ENGINE MODULE A: THE RAYCASTING & MATRIX MATHEMATICS (Doom/Wolfenstein Core)
--------------------------------------------------------------------------------
- Purpose: Vector mechanics and camera projection pipelines.
- Requirements:
  * Implement custom Vector2D/Vector3D classes handling cross products, 
    normalizations, and distance constraints without third-party math suites.
  * Construct a trigonometric lookup system caching mathematical angles (sin, cos) 
    to handle fast perspective projection, eliminating fish-eye lens distortion.
  * Build a digital differential analysis (DDA) raycasting engine tracing rays 
    through a grid matrix to calculate exact wall coordinate boundaries.

--------------------------------------------------------------------------------
2. ENGINE MODULE B: THE SYSTEMIC SHADING & VRAM RASTERIZER (ASCII Visuals)
--------------------------------------------------------------------------------
- Purpose: Process distance data into an interactive visual display.
- Requirements:
  * Map floating-point ray distances to an dynamic ASCII depth gradient chart 
    (e.g., close surfaces render as '#', distant horizons fade into '.').
  * Implement wall-side illumination shading: distinguish between North/South 
    and East/West wall intersections by altering character intensity to create 
    structural shadows, directly mimicking the original Wolfenstein 3D rendering style.
  * Project vertical wall slices onto a double-buffered 2D text matrix (Video RAM), 
    complete with strict viewport clipping limits to guarantee zero index errors.

--------------------------------------------------------------------------------
3. ENGINE MODULE C: PHYSICAL BOUNDARIES & ENTITY STATES (Immersive Physics)
--------------------------------------------------------------------------------
- Purpose: Manage movement vectors and spatial physical interaction.
- Requirements:
  * Maintain a comprehensive dungeon topology matrix featuring variable block IDs 
    representing solid walls, interactive security doors, and item containers.
  * Implement an Axis-Aligned Bounding Box (AABB) sliding physics loop. When the 
    player collides with a wall vector, the engine must calculate tangential velocity 
    allowing the player to seamlessly slide along the surface instead of getting stuck.

--------------------------------------------------------------------------------
4. ENGINE MODULE D: THE DEUS EX / SYSTEM SHOCK CHRONICLE ENGINE (Lore & Quests)
--------------------------------------------------------------------------------
- Purpose: Generate, track, and endlessly extend a dark, branching cyber-narrative.
- Requirements:
  * Implement a stateful Lore-Graph Tracking Machine recording global plot flags, 
    player allegiances, faction reputations, and key inventory item IDs.
  * Procedurally generate deep environmental logs, emails, and corrupted audio 
    transcripts mimicking the tone of System Shock. These must be dynamically 
    injected into terminal coordinate blocks across the 3D map.
  * Establish a Deus Ex-style objective engine offering multi-vector resolutions 
    to tasks (e.g., a locked passage can be bypassed by discovering a keycode log 
    in a text terminal, finding a structural ventilation route, or hacking a map array).
  * CONTINUITY REQUIREMENT: Every time you compile, read the previous code's 
    narrative database. Preserve all established lore, characters, and terminal 
    history, but extend the timeline forward by introducing new deeper levels, 
    conspiracies, and shifting world events.

--------------------------------------------------------------------------------
5. ENGINE MODULE E: SIMULATION FRAME ASSEMBLER & HUD (I/O Display)
--------------------------------------------------------------------------------
- Purpose: Consolidate visuals and narrative feedback into a single view.
- Requirements:
  * Render a real-time tactical Heads-Up Display (HUD) overlaying an ASCII 
    minimap, spatial orientation compasses, and player biometric tracking.
  * Dedicate a section of the frame output to a scrolling textual narrative console 
    displaying ongoing environment subtitles, log text reading, and quest updates.
