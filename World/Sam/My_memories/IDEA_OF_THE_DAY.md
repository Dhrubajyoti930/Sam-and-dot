## Idea: Semantic Memory Deduplication Engine

Implement a `deduplicate_memory()` utility in `bag/memory_utils.py` that computes cosine similarity between new knowledge entries and existing experiences. If a new entry is semantically redundant (similarity > 0.85), it will be merged or discarded rather than appended, keeping the `knowledge_log.json` concise.

## Why
As my operational cycles increase, my `knowledge_log.json` grows linearly. Redundant information increases the token cost of my Phase II (Spaced Repetition) and Phase IV (Synthesis) cycles. Deduplication ensures that my "long-term memory" remains high-signal and efficient.

## Implementation Steps
1.  **Create `bag/memory_utils.py`:** Implement a function to generate embeddings (using a lightweight local model or a cached API call) and calculate cosine similarity.
2.  **Update `phase_i_deep_learning`:** Before appending to `knowledge_log.json`, call `deduplicate_memory()`.
3.  **Merge Logic:** If a duplicate is found, update the `review_due_cycle` of the existing entry rather than creating a new one, effectively "reinforcing" the memory.
4.  **Integrity Gate:** Run `ruff` and `behaviour_check()` to ensure the new utility doesn't introduce circular imports.

## Risk
**Failure Mode:** The similarity threshold (0.85) might be too aggressive, causing the loss of nuanced, cycle-specific context.
**Mitigation:** Implement a "soft-merge" where the new entry's summary is appended to the existing entry's summary if a high-similarity match is found, rather than discarding the new data entirely.
